# PRD: «Карьерный дневник»

**Версия:** 1.0 (первая версия продукта)
**Дата:** 2026-11-15
**Статус:** согласовано, готово к реализации
**Стек:** React + Vite (JavaScript/JSX)

---

## 1. Для кого и какую задачу решает

**Аудитория:** студенты и начинающие специалисты (junior, стажёры), которые одновременно откликаются в 5–20 компаний и проходят несколько этапов отбора параллельно.

**Боль:** отклики, дедлайны тестовых заданий и даты собеседований живут в заметках, чатах и почте. Забывается, на каком этапе какая вакансия, что нужно сдать на этой неделе и куда писать, если ответа нет.

**Задача:** один локальный список вакансий, где по каждой видно текущий этап и ближайшую дату, а список отсортирован так, что «что горит» — сверху.

**Ограничение:** однопользовательское приложение без регистрации и сервера.

---

## 2. Основной пользовательский сценарий

Студент открывает приложение → нажимает «+ Вакансия» → заполняет компанию, должность, статус, дедлайн тестового и дату собеседования → сохраняет и видит карточку в списке с датой и подсветкой «через 2 дня» → меняет статус по мере прохождения этапов и удаляет отказ.

**Функции сценария (5):** создание · просмотр в списке · редактирование/смена статуса · видимость ближайшей даты · удаление.

## 3. Экраны и элементы интерфейса

### 3.1 Выбранный вариант: один экран + модальное окно формы

```
┌ Карьерный дневник ───────────────────────── [+ Вакансия] ┐
│ [поиск…]  [Все 6] [Отклик 2] [Скрининг 1] …               │
│ Всего: 6 · Просрочено: 1                                  │
│ ┌───────────────────────────────────────────────────────┐ │
│ │ Яндекс · Стажёр-аналитик                     [Тестовое] │ │
│ │ Тестовое: сегодня      Собеседование: 20 ноя           │ │
│ │ https://…                        Изменить      Удалить  │ │
│ └───────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────┘
```

Схема условна. Фильтр статусов — Apple Segmented Control; действия карточки — текстовые кнопки в футере; визуальные детали — по `DESIGN.md`. В фильтре используется короткая подпись «Тестовое», в бейдже и форме — полное «Тестовое задание».

### 3.2 Связанные состояния одного экрана

1. **Список** — карточки вакансий, тулбар (поиск + фильтр по статусу + счётчик «Всего» / «Показано N из M»).
2. **Пустое состояние** — текст «Пока ни одной вакансии», кнопки «Добавить первую» и «Загрузить примеры», подсказка про локальное хранение и демо-данные.
3. **Модальное окно формы** — создание и редактирование (одна форма, поля предзаполнены при редактировании).
4. **Диалог подтверждения** — удаление и закрытие формы с несохранёнными изменениями.
5. **Пустой результат фильтра** — «Ничего не найдено» + кнопка «Сбросить фильтры».
6. **Уведомление об успехе** — «Вакансия добавлена» / «Изменения сохранены» / «Вакансия удалена» + подсветка изменённой карточки и прокрутка к ней.

### 3.3 Элементы карточки

- компания, должность;
- бейдж статуса с цветом;
- бейдж дедлайна тестового;
- бейдж даты собеседования;
- относительная подпись («сегодня», «завтра», «через 3 дн.», «просрочено на 2 дн.») и рядом календарная дата («· 17 нояб.»);
- для прошедшего собеседования — нейтральная подпись «прошло N дн. назад» вместо «просрочено»;
- ссылка на вакансию (если указана; при отсутствии строка не показывается);
- кнопки «Изменить» и «Удалить».

### 3.4 Элементы формы

| Поле | Тип | Обязательное |
|---|---|---|
| Компания | text | да |
| Должность | text | да |
| Статус | select (по умолчанию «Отклик») | да |
| Дедлайн тестового | date | нет |
| Дата собеседования | date | нет |
| Ссылка на вакансию | url | нет |
| Заметки | textarea | нет |

Кнопки «Сохранить» / «Отмена».

### 3.5 Отклонённые варианты

- **B. Master-detail** (список + боковая панель деталей) — ближе к Notion/Trello, но больше вёрстки.
- **C. Два экрана с роутингом** (`/vacancy/:id`) — лучше для роста проекта, но лишняя сложность для базового интерфейса.

Оба варианта можно вернуть на этапе доработки внешнего вида.

## 4. Функции первой версии

1. Создание вакансии через модальную форму с валидацией обязательных полей.
2. Список вакансий с сортировкой: просроченные дедлайны тестовых → ближайшие будущие даты → остальные (включая прошедшие собеседования) по времени изменения.
3. Статусы с фиксированным набором: **Отклик, Скрининг, Тестовое задание, Интервью, Оффер, Отказ** (+ цветовая маркировка).
4. Дедлайн тестового и дата собеседования с относительной и календарной подписью, подсветкой «≤ 2 дней»; просроченным считается только прошедший дедлайн тестового, прошедшее собеседование показывается нейтрально.
5. Поиск по компании/должности (без учёта регистра и «ё») и фильтр по статусу со счётчиками; статусы с нулём недоступны.
6. Редактирование и удаление (с подтверждением).
7. Сохранение в `localStorage` и восстановление после перезагрузки.
8. Пустое состояние и кнопка «Загрузить примеры» (5 демо-вакансий, только при пустом списке).
9. Базовые тексты на русском, простая адаптивная вёрстка (один столбец на мобильном).

- Автотесты.
- Полировка дизайна — отдельный этап после базового интерфейса.

## 6. Где хранятся данные

**Хранение:** браузерный `localStorage`, ключ `career-diary.v1`. Никаких сетевых запросов.

```json
{
  "version": 1,
  "vacancies": [
    {
      "id": "uuid",
      "company": "Яндекс",
      "position": "Стажёр-аналитик",
      "status": "test",
      "testDeadline": "2026-11-17",
      "nextInterviewAt": "2026-11-20",
      "link": "https://...",
      "notes": "Созвон с рекрутером в 15:00",
      "createdAt": "2026-11-15T10:00:00.000Z",
      "updatedAt": "2026-11-15T10:00:00.000Z"
    }
  ]
}
```

**Статусы:** `applied` | `screening` | `test` | `interview` | `offer` | `rejected`.

**Даты** — только `YYYY-MM-DD` (локальные, без времени); сравнение по календарной дате, чтобы не ловить сдвиг часового пояса.

**Демо-данные:** 5 записей в `src/lib/sampleData.js` — по одной на ключевые статусы, с датой в прошлом (просрочка), сегодня, +2 дня, +7 дней и без даты. Загружаются кнопкой, не автоматически.

## 7. Технические решения

- **Стек:** React 19 + Vite 7, JavaScript + JSX, без UI-библиотек, без роутера, без date-библиотек.
- **Пакетный менеджер:** npm.
- **Состояние:** один `useState` со списком вакансий + `useEffect` на сохранение; бизнес-логика в маленьких модулях.
- **Структура файлов:**

```
ИДЗ1/
  PRD.md, DESIGN.md, spec.md, README.md, reference.jpeg
  site/
    package.json, vite.config.js, index.html
    src/main.jsx, src/App.jsx, src/styles.css
    src/components/VacancyCard.jsx, VacancyFormModal.jsx, ConfirmDialog.jsx,
                   Toolbar.jsx, EmptyState.jsx, StatusBadge.jsx, DateBadge.jsx
    src/lib/storage.js, src/lib/dates.js, src/lib/statuses.js, src/lib/sampleData.js
    src/hooks/useVacancies.js
```

Все файлы приложения лежат в `site/`; документация и референс — рядом, в корне репозитория.

- **Скрипты:** `npm run dev` (http://localhost:5173), `npm run build`, `npm run preview`.
- **Валидация:** компания и должность обязательны (trim, ошибки под полем, сохранение блокируется); ссылка опциональна, `input type="url"` + проверка протокола; даты опциональны.
- **Доступность/UX-мелочи:** `label` у полей, закрытие модалки по Esc, фокус в первом поле при открытии, подтверждение при закрытии «грязной» формы, `aria-live` для счётчика.

## 8. Крайние случаи и поведение

- `localStorage` недоступен/переполнен → приложение работает в памяти, показывает предупреждение «Данные не сохраняются».
- Битый JSON в хранилище → список пустой, предупреждение и предложение загрузить примеры (без падения приложения).
- Пустой результат поиска/фильтра → отдельное сообщение и сброс фильтров.
- Длинные названия и заметки → обрезка в карточке (CSS ellipsis), полностью видны в форме.
- Дедлайн тестового в прошлом → красный бейдж «просрочено на N дн.» и приоритет в сортировке.
- Собеседование в прошлом → нейтральный бейдж «прошло N дн. назад», в счётчик «Просрочено» не попадает.
- Битый JSON → предупреждение остаётся до первой успешной записи (добавление или «Загрузить примеры»), затем исчезает.
- Удаление → подтверждение; после перезагрузки запись не возвращается.

## 9. Три конкретные проверки результата

1. **Создание и сохранение.** Добавить «Яндекс / Стажёр-аналитик», статус «Тестовое», дедлайн = сегодня + 2 дня. Ожидаемо: карточка в списке с оранжевым бейджем «через 2 дн.»; после F5 карточка на месте.
2. **Сортировка и фильтры.** Загрузить примеры: 3 вакансии с разными датами + 1 без даты. Ожидаемо: просроченная первая, затем ближайшие по возрастанию, без даты — в конце; фильтр «Оффер» оставляет только оффер; поиск «яндекс» — только совпадения; при пустом результате — «Ничего не найдено» и сброс.
3. **Валидация, редактирование, удаление.** Сохранить форму с пустыми компанией и должностью → ошибки, окно не закрывается; изменить дедлайн существующей вакансии → бейдж пересчитался; удалить вакансию → подтверждение, запись исчезает и не возвращается после F5. Плюс `npm run build` проходит без ошибок.

### 2026-11-15. UX-итерация 2 (правки P0 по разбору сценария)

Разбор сценария и проверка эдж кейсов выявили 2 бага и 8 разрывов в интерфейсе. Исправлено:

- **Прошедшие даты.** Прошедшее собеседование больше не «просрочено»: нейтральный бейдж «прошло N дн. назад», не попадает в счётчик «Просрочено» и не висит в топе. Просроченным считается только дедлайн тестового; сортировка: просроченные тестовые → будущие даты → остальные по времени изменения (`src/lib/dates.js`, `src/App.jsx`).
- **Календарная дата.** Рядом с относительной подписью всегда видна дата: «Тестовое: через 2 дн. · 17 нояб.» — работает и на мобильном, где tooltip недоступен (`DateBadge.jsx`).
- **Обратная связь.** После сохранения/удаления — уведомление «Вакансия добавлена» / «Изменения сохранены» / «Вакансия удалена», изменённая карточка подсвечивается и прокручивается в зону видимости (`App.jsx`, `styles.css`).
- **Фокус и клавиатура.** После закрытия модалки фокус возвращается на кнопку-источник, Tab больше не уходит за пределы формы и диалога (`VacancyFormModal.jsx`, `ConfirmDialog.jsx`, `App.jsx`).
- **Шум в карточке.** Убрана повторяющаяся строка «Ссылка не указана»; футер показывается только с действиями (`VacancyCard.jsx`).
- **Поиск.** Не зависит от «ё» и регистра: «стажер» находит «Стажёр» (`App.jsx`).
- **Счётчик.** При активном фильтре — «Показано N из M», иначе «Всего: N» (`App.jsx`).
- **Нулевые статусы.** Чипы с 0 недоступны для нажатия (`Toolbar.jsx`).
- **Пустое состояние.** Подсказка: данные хранятся в этом браузере, примеры демонстрационные (`EmptyState.jsx`).
- **Баннер о повреждённых данных** теперь исчезает после первой успешной записи; попутно убрано сохранение на монтировании, из-за которого StrictMode в dev затирал повреждённые данные и гасил предупреждение (`useVacancies.js`).
